# Scene fix tools

Tools for repairing a scene's master after it is accepted: built for the overworld, and used the same way for the five
interiors. Every tool takes the scene from `SCENE=<id>` (`overworld` when unset; `moosylvania`, `slu`, `foundry`,
`side-project`, `brennans`). The data lives in `art/sources/<scene>-fix/`: `stitched.png` is the editable native master
(1983 × 793 for the [overworld](../../../art/sources/overworld-fix/), 1672 × 941 for the SLU lab, the Foundry theatre, the Side Project bar and Brennan's, 887 × 1774 for the Moosylvania lobby),
`rounds/round-N.json` the round specs, `tiles/` and `tilemap.json` the current round's working set. Each scene's background
is its `stitched.png` upscaled 4×; see [the art workflow](../../../art/README.md), "Filling the map and sharpening it" and
"Interiors". Every command runs from any directory.

| File | Purpose |

| `tile-manifest.py` | Writes the Codex manifest for a round's tiles and prints the commands that run them |
| `edit-api.sh` | Runs a round's tiles through `gpt-image-2.5-sunburst` on the Images API edit endpoint with the mask |
| `install-master.sh` | Upscales `stitched.png` 4×, composites the fix folder's `decals.json` decals (logos, lettering, small props) onto the upscale at full resolution, installs it as `<scene>-master`, then re-derives every asset the manifest derives from it (the plate with its tiles, and the measured mattes) and lists Codex extractions whose crop the round changed |
| `lot-stripes.py` | Round fifteen's hand-drawn tile: relays the Maplewood parking lot as flat asphalt with straight, evenly spaced stall lines (`tiles/t-lot-model.png`) |
| `lobby-railings-floor.py` | The Moosylvania lobby's round five, drawn by construction: paints the old railing infill out of the native master, relays the stair treads' back edges and the two office floors beneath the loft as that round's tiles (`tiles/t-<name>-model.png`), and writes the railings' balusters and sub-rails as the lobby's decals (`loft-railing.svg`, `stairs-left-railings.svg`, `stairs-right-railings.svg`) |
| `signs.py` | The overworld's two Maplewood signs, drawn by construction: the welcome board with the site's badge and the directory board of six lettered district plaques that replaced the fingerpost. Writes `art/sources/welcome.png` and `art/sources/signpost.png`; then `npm run art -- process welcome --force` and `process signpost --force`. | `sync-geometry.py` | Copies the re-derived extractions' world rects into `src/lib/scenes/overworld.ts` (install-master runs it for the overworld) |
| `assembly/` | The earlier regional-edit scripts (`assemble.py`, `assemble2.py` with `regions.json`, `bridge-restore.py`, `paste-mc.py`) and `rivermask.py`, which traced the river polygon; kept as a record, their inputs are gone |

## A round

Prefix every command with `SCENE=<id>` for an interior.

1. Mark the defects: red loops on `tiles/t-<name>-out.png` (the standard 512 px grid, regenerated by every stitch; a
   1672 × 941 interior's grid is four columns by two rows, `c0r0` to `c3r1`, and the lobby's two columns by four rows, `c0r0`
   to `c1r3`), or on a copy of the whole master. A scene's first round has no grid tiles yet (a stitch writes them), so mark
   a copy of the whole master. Commit and push.
2. Find the loops: `tiles.py detect <git-ref>` (loops drawn on tiles since that commit) or `tiles.py detect-master <png>`,
   filled into `rounds/detected/`. Loops described in words are placed as rectangles or polygons instead.
3. Write `rounds/round-N.json` with `"base": "stitched.png"`, then `tiles.py prepare rounds/round-N.json`. It keeps the
   current master aside as `rounds/base-N.png`, cuts each tile, and writes its mask (white = repaint), its red-outlined
   copy and its prompt. A repaint area ends well inside its tile and crosses a road only at a junction: the model lines
   its redraw up with what the reference shows, so a road that leaves the area needs its continuation in the tile.
   A smaller tile (256 px) is drawn at about four times the master's resolution.
4. Redraw the tiles, one of:
   - Codex (`gpt-image-2`; the CLI cannot select 2.5): `tile-manifest.py rounds/round-N.json`, run the printed
     `npm run art -- generate ...` commands, compare the attempts, and copy the one you keep to `tiles/t-<name>-model.png`.
   - The Images API with `gpt-image-2.5-sunburst`: `edit-api.sh [tile ...]` with `OPENAI_API_KEY` exported in the shell,
     never written to a file.
   - By hand: paint on a copy of `t-<name>.png` and save it as `t-<name>-model.png`.
5. `tiles.py stitch` pastes each model tile back only inside its mask. It rejects an output the model zoomed or panned
   (mean drift over 14 outside the mask), runs the round's deterministic ops, proves that no pixel outside the touched
   areas changed, and refreshes every `-out.png`. `tiles.py check` then lists any road that dead-ends at an edited edge.
   Read the result at 4× to 8× before installing; a protected rectangle keeps every pixel inside it, haze included.
   `check` and the deterministic ops below read the overworld's lawn, footpath and water colours; an interior uses model
   tiles, `restore`, `paints` and `stamps`.
6. `install-master.sh <round> "<note>"` upscales and installs the master (Upscayl `digital-art-4x`; deterministic, so an
   unchanged `stitched.png` reinstalls byte for byte). A Codex extraction it lists as STALE was drawn from pixels the
   round changed: regenerate it with `--keep-masters` and judge it. Then run `npm run art:review`, read the mattes over the
   plate (the Eads Bridge on the overworld), and record the round under `art/reviews/` with current asset hashes.

## Deterministic ops

A round spec can also carry ops that run after the pastes, for what the model keeps getting wrong. Each edits pixels
only inside the area it records, and the stitch proof covers them.

- `lawnfill` / `ghostfill` / `blurfill` / `forcefill` / `waterfill` / `shorefill` / `pathfill` / `cleanup`: loops (with
  `<kind>Extra` rectangles, `<kind>Polygons` and `<kind>Protect`) whose trees, ghosts, blur, water, shoreline or stray
  path are relaid, by lawn cloned per cell from real lawn with a tone match, or by the lake's own water and sand.
- `restore`: base pixels put back in a rectangle, or `{rect, src}` from an earlier round's base.
- `tones`: a lawn tone shift in a rectangle or polygon, fading out along x, or colour-keyed (`from`/`to`).
- `paints`: a flat colour in a rectangle or polygon (polygons touch only light pixels unless `all`).
- `shorebands` / `roadbands`: a jagged shore path or road redrawn as one clean band on its fitted edges.
- `sandfills`: a wide sand band between a shore path and the water relaid as lawn, keeping a thin rim.
- `bridges`, `stamps` and tile `corridors`: a path stub carried on to the path beyond, a tree cloned from elsewhere,
  the base path's own line handed to the repaint area up to its junction.
- A tile's `keepBaseWater` (true, or master rectangles) keeps the base wherever base and model are both water; keep it
  off where old strokes are water-coloured.
