# Scene artwork pipeline

Issue 02 provides the same terminal workflow for Codex, Claude Code and a human builder. `codex exec -i` calls authenticated Codex image generation with references attached. No ChatGPT browser session or OpenAI API key is needed for this provider. Generation was exercised with Codex CLI 0.156.1 on 2026-09-24.

Requirements: Node 24+, ImageMagick 7 (`magick`), and authenticated Codex CLI with image generation. Run from the repository root. `npm install` installs the existing TypeScript tooling.

```sh
npm run art -- list
# Generate missing assets, in dependency order.
npm run art -- generate all
# Revise layers while preserving the approved composition.
npm run art -- generate scene:moosylvania --force --keep-masters
npm run art -- generate welcome --force
# Reprocess saved local PNGs after correcting placement (no generation).
npm run art -- process welcome --force
npm run art -- process door --source /absolute/path/to/door.png --force
npm run art:review
python3 -m http.server 4174 --bind 127.0.0.1
```

Open [the scene workshop](http://127.0.0.1:4174/art/review.html). There are **seven scenes**: the overworld and six interiors. Maplewood is a district within the overworld. The original prototype remains a historical style reference; it is not an eighth scene.

## Compose first, then separate layers

Each `*-master` reference is a complete composition. Location photos supply architectural details; the original daytime illustration supplies the brighter cyan, green, cream and coral palette. See [landmarks.md](landmarks.md) and [the source ledger](references/locations.json). Photos and satellite screenshots are local references, never shipped artwork. Recreating a master on another machine requires restoring the selected images to the listed `art/references/local/` paths. Missing references produce a clear error; committed outputs and the workshop work without this local photo pack.

1. Generate and inspect a master: `npm run art -- generate moosylvania-master --force`. Judge it against the real room photographs before extracting anything. To iterate on an accepted draft, copy it to `references/local/drafts/`, attach it as a composition reference and give the prompt a short fix list; the overworld master was settled this way in two runs.
2. Choose each movable object's crop in the master. `registration.rect` is that crop in scene world coordinates. The pipeline attaches the exact crop as the final reference. The objects stay in the background plate.
3. Generate the layers with `--force --keep-masters`. Do not regenerate an approved master accidentally. The background plate is the master itself (`deriveFrom`), so every object stays painted in and its cut-out draws over its own pixels. An explicit `world` rectangle anchors the trimmed object to measured fixture bounds; otherwise placement derives from its source crop and trim offset. Inspect both: models sometimes recenter or resize extracted objects despite the prompt.
4. For precise extraction without redrawing, `deriveFrom` plus `registration.mask` copies the original composition pixels through a measured polygon matte. Mask points are normalized to the registration crop. The SLU lab's cut-outs (whiteboard, lit monitor, diploma and the four desks) the Foundry theatre's (the three posters, the screen, the three seat rows and the projector ledge) the Side Project bar's (the eleven brand bottles, rearranged on 2026-09-30 [review](reviews/2026-09-30-side-project-bottles.md), the door sign, the chalkboard and the two counters) Brennan's (the five cigar boxes, the STG plaque, the café table set, the lounge and the sofa) the Bread Co. café's (the ATM, the scan-to-pay stand, the usability test's laptop, cup and clipboard, the counter and the two table sets) and the Moosylvania lobby's (the four loft computers, the moose statue, the meeting TV, fourteen walk-behind units and the two groups of hanging lanterns) were traced this way from the start. Each desk, with its monitor, keyboard and chair, is walk-behind scenery (kind `scenery`); its matte polygon in world px is also its outline in `src/lib/scenes/slu.ts`, beside a front line through its front feet. The Foundry's seat rows and projector ledge are walk-behind scenery the same way (`src/lib/scenes/foundry.ts`), as are the Side Project bar's two counters (`src/lib/scenes/side-project.ts`), Brennan's café table set and lounge (`src/lib/scenes/brennans.ts`), the Bread Co. café's counter and two table sets (`src/lib/scenes/bread-co.ts`) and the Moosylvania lobby's loft desks, lounge armchairs, moose wall, round sofas and meeting furniture (`src/lib/scenes/moosylvania.ts`). Brennan's and the lobby's furniture mattes are traced from the pixels, the floor between its legs cut out: a matte is one polygon, so its holes join the outer contour by zero-width slits, and its outline is the piece's convex hull, so a cursor keeps its side until it steps off the whole piece. `deriveFrom` without a mask copies the composition, as the overworld plate does. The overworld's two foreground trees, the marquee bulb string and the Eads Bridge are masked mattes: Codex redrew all four when asked to extract them, so their cut-outs are the master's own pixels through a traced or hand-measured polygon (a thin halo of surrounding plate pixels is invisible at rest because it lands on identical pixels). The Poplar Street bridge's span over the river, its deck and two piers, was a masked matte from the start (2026-09-30, [review](reviews/2026-09-30-overworld-poplar-bridge.md)): the site draws both bridges over a cursor in the river.
5. Reprocess after a rectangle change; regenerate dependent layers after a master change, then inspect all placements again. Coordinate annotations belong to that composition, not to arbitrary future camera angles.

The four Moosylvania computer targets are four lit monitors on existing loft desks. They are not four cloned furniture sprites. Foreground seats face the Alamo screen; the Side Project bottles stand on the shelf behind the bar; the Brennan's cigar boxes stand on easels inside the humidor, their lids in its perspective. Foreground scenery never covers a prop: Brennan's sofa, cut by the frame's lower right corner, is foreground and clear of the humidor, and the lobby's hanging lanterns hang along its walls, clear of the loft. The validator rejects foreground/prop bounding-box overlaps.

The Codex image tool accepts **at most five reference images** (the registration crop counts as one; the pipeline refuses more) and returns its own native size: about 1774 × 887 for a 2:1 prompt, 1983 × 793 for 2.5:1, 1254 × 1254 for a square, 887 × 1774 for a 1:2 portrait; `size` values in the manifest are those native canvases. It cannot be told a pixel size; earlier 2048 and 2304 wide masters were `sips` upscales made by the Codex agent, and the pipeline now asks for the native file unresized. Upscaling to the plate size is the pipeline's job.

`generate backgrounds` selects seven plates; `generate furnishings` selects interior scenery, props and foreground. Existing outputs are retained unless `--force` is present. `--keep-masters` preserves reference assets even with `--force`. Run one generator per asset at a time; independent scenes may run concurrently after shared dependencies exist. `generate <asset> --dry-run` writes its full prompt and checks available references. Processing stages outputs before replacement so failure leaves the previous asset intact.

## The overworld

### Filling the map and sharpening it

The accepted overworld master is a chain of regional edits on one composition, each recorded in the master's `prompt.txt` and `provenance.json`: crop a region of the current master to a native canvas (`references/local/drafts/fill-crop-<region>.png`), hand-prepare it when placement or scale matters (clear an area to flat lawn, paste a scaled-down building, mark a footprint), let Codex redraw the crop with a preserve-list and a change-list, then paste it back with a feathered border (`scripts/art/overworld/assembly/assemble.py`, `assemble2.py`, with `regions.json`; a hard cut where a seam crosses a structure such as the Eads Bridge, and protected rectangles where a prop's ground must not move). Codex keeps what the crop shows and ignores size prose, so scale corrections are done in the prepared crop, not the prompt. Fill scenery between the key scenes follows real St. Louis (Google Places photos under `references/local/places/fill/`, attributions in `references/locations.json`): Forest Park, the medical campus, downtown, Laclede's Landing, the Arch grounds, Soulard and the brewery, the Illinois riverside and Belleville, plus ordinary housing, shops and schools; main scenes stay large, background landmarks sit at roughly their real proportion to the Arch.

Seams are where regional edits fail: an edit redraws a road, a roof or a bridge a few pixels off, and the feathered paste leaves a ghost. Clip each edit to the ground it was meant to change (a road's top edge, a roof line, a bridge deck band) and keep the base elsewhere; where a structure crosses a seam, copy it back wholesale from the base along a band that hugs its outline (the Eads Bridge). Super-resolution does not hide seams: a Real-ESRGAN 4× pass sharpened seam blur into visible artifacts, which is why the seams were fixed first on the tile map below.

**The overworld background is a 4× upscale of the stitched master (2026-09-25, keep it).** The editable source of truth is the native 1983 × 793 `sources/overworld-fix/stitched.png`; every fix is made there. `generated/overworld/overworld-master/image.webp` is that image upscaled 4× to 7932 × 3172 by Real-ESRGAN (Upscayl `upscayl-bin`, model `digital-art-4x`; Lanczos stays soft and `ultrasharp` invents texture). The scrollable background plate (13500 × 5400), its tiles at both densities and the five master-derived mattes are all cut from that 4× master, so the plate is a 1.7× resize of sharp pixels instead of a 6.8× resize of the native one. Registration rects are in world coordinates and scale to any master size, so scene geometry does not change. After every fix round, reinstall with `scripts/art/overworld/install-master.sh <round> "<note>"`: it upscales (deterministically), installs the master with its derivation record, re-derives the plate, tiles and mattes, syncs their world rects into `src/lib/scenes/overworld.ts` and validates. Then read the bridge matte over the plate and record the round under `reviews/`. A logo too fine for the native master is a decal: `sources/overworld-fix/decals.json` places the SLU logomark (`slu-logomark.svg`, supplied by Joe) on McDonnell Douglas Hall's central parapet in native px, and the install composites it onto the 4× upscale at full resolution (2026-09-29). Pasted at native size, the 4× upscale blurred its fleur-de-lis. Lettering and small props too fine for the native master are decals the same way (2026-09-30, [review](reviews/2026-09-30-overworld-round-19.md)): the FOREST PARK sign's face with its lettering (`forest-park-sign.svg`, Barlow Condensed as outlines) and Forest Park's three picnic tables (`picnic-tables.svg`), each drawn in native px so its viewBox is the master's own coordinates; round nineteen painted the old tables out underneath. The MIDTOWN and BELLEVILLE signs' lettering is a decal each too (2026-10-07, [review](reviews/2026-10-07-overworld-round-22.md)): round twenty-two relaid each native board's whole front face as the MAPLEWOOD and CENTRAL WEST END boards' wood (flat red-brown, faint streaks, two plank seams, two nail heads), the old lettering gone (a part repaint showed its edges in the upscale), and `scripts/art/overworld/district-signs.py` writes both that round's tiles and the two decals, white as every sign's lettering is. ImageMagick's own SVG renderer draws them, which ignores strokes and nested transforms, so a decal's SVG is flat filled polygons and paths with baked coordinates. A small building is a decal too when its detail is too fine (2026-10-01, [review](reviews/2026-10-01-overworld-bread-co.md)): round twenty replaced the shop east of Ted Drewes with the St. Louis Bread Co., Codex's drawing of it placed on the native master by hand because no attempt held the tile's registration, and the same cut-out at the drawing's own resolution (`bread-co-building.png`) is composited over it on the upscale, where its windows, patio and shrubs had come out as blobs; `scripts/art/overworld/bread-co-sign.py` raises that cut-out's parapet, sets the Saint Louis Bread Co. logo Joe supplied into its front wall on a sage board and recolours its cream outline to the ground under it, which round twenty-one relaid by hand (`bread-co-lot.py`): lawn to the building on both sides, with straight edges to the paving.

Small defects are fixed on an exact tile map, never by regional redraws (2026-09-25). The tools and the round workflow are in [`scripts/art/overworld/`](../scripts/art/overworld/README.md); the data (`stitched.png`, the round specs and the last round's working set) is in `sources/overworld-fix/`, committed like the interiors' `sources/<scene>-fix/`, so it is reachable from any machine. Model tiles are pasted back only inside their masks and the stitch proves that nothing outside them changed. Lessons that shaped the tools:

- A repaint area ends well inside its tile and crosses a road only at a junction: the model lines its redraw up with what the reference shows beyond the area, so a road leaving the area needs its continuation in the tile (the lake ring's exits stepped at a tile edge until the tile was widened). `tiles.py check` lists every road that dead-ends at an edited edge.
- Asked to delete a tree, the model draws a new one. Deletions, ghost trees, blurred lawn, water and shore strips, a jagged shore path or road, and tone steps are fixed deterministically instead (lawn cloned from real lawn per cell with a tone match, the lake's own water and sand, fitted bands).
- The model sometimes zooms or pans a tile (a whole-park redraw came back 7 % larger); the stitch rejects an output whose drift outside the mask is too high, and a strict-registration line in the prompt fixes most reruns. A smaller tile (256 px) is drawn at about four times the master's resolution, which cleans a single building best.
- A protected rectangle keeps every pixel inside it, haze included, and an object reaching past it is cut straight at its edge: read each protect edge in the 4× upscale. Keeping the base water where base and model are both water hides a retinted box but also keeps old water-coloured strokes (the Eads lamp hooks, the old hangers), so limit it to the area that needs it.
- The Codex CLI's image tool is fixed to `gpt-image-2` at automatic quality (`codex-rs/ext/image-generation/src/tool.rs`); `gpt-image-2.5-sunburst` with `xhigh` or `max` quality is only reachable through the Images API edit endpoint (`edit-api.sh`, with `OPENAI_API_KEY` exported and never written to a file).


The overworld master is one Cursor Camp style diorama: an elevated three-quarter view, north up, one continuous ground plane with a thin skyline band, about a dozen large landmarks and connected cream footpaths, so a 32 world px cursor reads as person scale beside an 80 px doorway. A Cursor Camp screenshot (`references/local/cursor-camp/`, logged in `references/locations.json`) is attached only for camera angle and object scale; the style and palette still come from the original daytime illustration. The five district signs and the MonsterCommerce roof sign are the only lettering requested.

Square crops use `1024x1024`; the marquee uses a 3:2 crop with `1536x1024` and the bridge a 2.5:1 crop with `1983x793`, because the extraction canvas must keep the crop's aspect ratio. The welcome board, fingerpost, bike, park notice board, start/finish sign, moose rig and rider rig are standalone cut-outs placed by `world` rects and `sceneLayouts` (the accepted master paints no bike, notice board or start sign, so each is generated against the park at bench scale; the sign stands where round seventeen removed a bench, [review](reviews/2026-09-29-overworld-start-sign.md), and is scenery, while the bike and the notice board stand on the lawn west of the gazebo north of the lake, clear of the lake loop, [review](reviews/2026-09-29-overworld-park-props.md)); they are re-placed with `process <id> --force`, not regenerated, when the master changes. The Moosylvania lobby's TV remote is a standalone cut-out the same way (2026-10-01, [review](reviews/2026-10-01-moosylvania-tv-remote.md)), the one interior prop not in its plate, since it leaves the meeting table while a visitor holds it; it is drawn by construction, `sources/moosylvania-tv-remote.svg`, as a decal's SVG is, not by a model. The rider rides the whole lake loop, `track` in `src/lib/scenes/overworld.ts` (buildout ticket 18); its `sceneLayouts` rect is where it rests under reduced motion, past the start line, with `travelX` 0. Its rig is cut from a pedal sheet (2026-09-30, [review](reviews/2026-09-30-overworld-rider-sheet.md)): `rider-sheet`, drawn against `rider-master` and kept lossless because its cells are keyed, holds the cyclist without wheels at eight crank angles and one bold five-spoke wheel. ## Interiors

The six interiors are iterated like the overworld (2026-09-25). Each has a committed native master, `sources/<scene>-fix/stitched.png`: the first five redrawn on 2026-09-28 (the 2048 × 1152 Codex masters of 2026-09-24 are in git history), the St. Louis Bread Co. café composed on 2026-10-01 ([review](reviews/2026-10-01-bread-co-cafe.md)). SLU's computer science lab, the Foundry's small auditorium, Side Project's front bar, Brennan's humidor wall and the Bread Co. café are 1672 × 941, Codex's own 16:9 canvas. The Moosylvania lobby's view up the nave is 887 × 1774, Codex's 1:2 canvas, for a 2400 × 4800 scene scrolled like the overworld. Each `generated/<scene>/<scene>-master` is that native master's 4× Real-ESRGAN upscale, and the plate derives from it, so a fix never redraws the room. Fix a defect or change a detail on the tile map with the [scene fix tools](../scripts/art/overworld/README.md) and `SCENE=<scene>`, then reinstall with `SCENE=<scene> scripts/art/overworld/install-master.sh <round> "<note>"`. Regular geometry too fine for a native master is a decal in an interior too (2026-10-01, [review](reviews/2026-10-01-moosylvania-railings-floor.md)): the lobby's loft railing and both staircases' railings came out of the upscale as a wobbly mesh, veins and blobs, so `scripts/art/overworld/lobby-railings-floor.py` paints the old infill out of the native master and draws straight sub-rails and evenly spaced balusters as `sources/moosylvania-fix/loft-railing.svg`, `stairs-left-railings.svg` and `stairs-right-railings.svg`, in native px; the same script relays the stair treads' back edges and the two office floors beneath the loft by construction, as that round's tiles. The café's mattes are traced by a kept script, `sources/bread-co-fix/rounds/mattes.py` (colour keys against verified seed points, hand polygons where colour cannot tell an object from what is behind it), and its scan-to-pay stand's QR pattern is a decal written by `rounds/qr-decal.py`. A 1672 × 941 master is not exactly the 2845 × 1600 world's shape, so a master px is 0.42539 world px across and 0.42508 down: a matte's registration rect is computed per axis, as `scripts/art/generate.ts` cuts its crop, or the crop lands a pixel or two low and is resampled. Until 2026-09-25 each plate was a Codex clean-plate redraw of the whole room with the props removed; every edge had drifted a pixel or two from the master (mean absolute error 2 to 8 %), and a fix would have meant another full redraw.

Measured mattes of the master (the seven SLU lab cut-outs, the eight Foundry cut-outs, the fourteen Side Project cut-outs, the nine Brennan's cut-outs, the eight Bread Co. cut-outs, the twenty-four lobby cut-outs) are re-derived by the install. The other cut-outs are Codex extractions, redrawn by the model: each covers its painted original, but none matches it pixel for pixel, so a round that touches its crop leaves it stale (the install lists it) and it is regenerated or replaced by a measured matte in issue 05's prop pass.

## Videos: the media host

The videos a prop's card or the Foundry screen plays are not in the build (2026-09-30). The site's own host answers a video whole, never by byte range, and takes no file over 25 MiB, so they are served from an R2 bucket's custom domain, the media host. The sources stay in `sources/videos/<folder>/`; `npm run videos` (`scripts/videos.ts`) gives every one of them, played yet or not, a key with its content's hash (`videos/<folder>/<name>.<hash>.mp4`), writes the map the site reads (`src/lib/video-files.json`) and uploads what the host hasn't got. A video plays once a prop's `video.file` or a Foundry reel names its file; the site names a video by its file alone, so no two folders may hold the same name.

- **Adding or replacing a video**: put the file in a folder of `sources/videos/`, run `npm run videos`, commit the map, then push. In that order: a build that names a key the bucket hasn't got plays nothing. `npm test` fails while the map is behind the scene data or a source.
- **Locally** nothing reaches the bucket: the dev server, a local build and the smokes fetch `/media/<key>`, which the dev and preview servers answer from the sources (`scripts/media.ts`). Only a Workers Builds build, `main` or a Preview, names the media host (`mediaUrl` in `scripts/build-env.ts`).
- **`npm run videos status`** says, for each video, whether its source is here and current and whether the host has it. **`npm run videos pull`** fetches the sources a checkout is missing from the host.
- **Nothing is ever deleted from the bucket**, which is the videos' backup too: a replaced video's old key stays there beside its new one, and a video whose source is deleted here keeps its place in the map, so `pull` brings it back. Removing one for good is done by hand, in the dashboard and the map.
- **Once, by hand** (the names are in `src/lib/video-files.json`): `npx wrangler login`, `npx wrangler r2 bucket create barmadden-media`, then connect `media.barmadden.com` to the bucket, in the dashboard under the bucket's Settings, Custom Domains, or with `npx wrangler r2 bucket domain add barmadden-media --domain media.barmadden.com --zone-id <barmadden.com's zone ID>`. The page policy already allows the host (`media-src`).
- **Out of git**: the sources are not committed (`art/sources/videos/` is ignored, 2026-09-30); the bucket is their home and their backup. A fresh checkout has none until `npm run videos pull` fetches them all from the host, and it needs them only to play a card's video in dev, a local build or the smokes: a Workers Builds build never reads them. The copies committed before then are still in git history.

## Files and coordinates

- `manifest.json`: prompts, dependencies, crop registration, reviewed placement and overworld rig layout. `style.txt`: brighter location-aware art direction.
- `sources/`, committed: `sources/<id>.png` is the original of each model-drawn asset (the moose rig and its master, the rider's master, pedal sheet and wheel, the welcome board, signpost, bike, ride sign, start sign, door, marquee, MonsterCommerce eye and server rack), which `process <id>` reads to re-key or re-place it; keep these, since a rerun draws a different image. A derived asset keeps no copy there, because `generate <id>` re-cuts it from its committed parent, and a scene master's 4× PNG is rebuilt by `install-master.sh`. The seven `sources/<scene>-fix/` folders hold each scene's editable native master, round specs and last tile-map round; their tools are in `scripts/art/overworld/`.
- `runs/<asset>/<timestamp>/`: ignored generation prompts, execution logs and model outputs.
- `generated/<scene>/<asset>/`: each scene's assets sit together in one folder (`generated/overworld/moose-head/`, `generated/slu/slu-whiteboard/`), and a background's folder repeats its scene's name (`generated/overworld/overworld/`). An asset's `file` and tile paths are relative to `generated/`. `generated/review.json` indexes every scene for the workshop.
- `image.webp` and `asset.json`: portable retained pixels, source SHA-256, trim offsets, placement and tile inventory. `provenance.json` records the matching generation run or derivation; generated prompts use `<repo>` instead of an absolute machine path.
- Background plates: **2 image px/world px** and **512 world px tiles** at **1.25×** and **2×**, cut from the scene's 4× master. The raster is resized before tiling. A source smaller than the plate would also get an `upscale.webp` companion at 2× (the `upscale` field); no current scene needs one.
- Cutouts: existing alpha, 10% magenta key, 2%/98% alpha endpoint clamp, 1 px erosion, tight trim, lossless WebP. Trim offsets remain in the source frame.
- Delivery sizes (2026-09-30, `scripts/art/deliver.ts`, [review](reviews/2026-09-30-cutout-delivery-sizes.md)): beside each cut-out's `image.webp`, `1.25.webp` and `2.webp` are what the site fetches, the cut-out resized (Lanczos, as the tiles are) to the size it is drawn at each tile density: its world rect, or a rig part as its rig is fitted into its `sceneLayouts` rect, and never larger than its original. One over 256 × 256 px is lossy like the tiles, quality 90 with sharp chroma and exact alpha, so its silhouette is the original's; a smaller one (the rider, the bike, a bottle) stays lossless, since lossy chroma softens a small prop's thin coloured lines and saves little. `image.webp` stays the lossless retained original that the workshop, the composites and every re-cut read, and it is no longer in the site's build: a 1167 px bike drawn 100 world px wide went from 291 KB to 33 KB at 2×, and the overworld's cut-outs together from 3.9 MiB to 0.63 MiB at 2× and 0.42 MiB at 1.25×. Every pipeline command writes the ones that are missing, the wrong size or encoded the other way (reprocessing an asset replaces its folder, so its own are rewritten); `npm run art:validate` and `npm test` fail on one that is missing or wrong. To rewrite one by hand, delete it and run `npm run art -- review`. Judge a changed cut-out on the site as well as in the workshop, which shows the original.
- `generated/overworld/<rig>-rig.json` (moose, rider, marquee and MonsterCommerce sign): prototype-compatible `{parent,x,y,w,h,pivot}` parts plus file paths. Pivots are normalized within the trimmed part; ancestor transforms operate in master space, or, for a part cut from a sprite sheet, relative to its `rig.anchor`, the point of its own source at the rig's origin. The moose and rider rigs are placed in the overworld's `sceneLayouts`.
- `generated/<scene>/<scene>-master/image.webp`: the 4× Real-ESRGAN upscale of `sources/<scene>-fix/stitched.png` (7932 × 3172 for the overworld, 6688 × 3764 for a 1672 × 941 interior, 3548 × 7096 for the lobby), the background's source. Edit the native stitched image, never the upscale; the one exception is the decals in `sources/<scene>-fix/decals.json`, which the install composites onto the upscale.
- `generated/<scene>/composite.webp` and `generated/contact-sheet.webp`: stitched inspection images, rebuilt by `npm run art:review`; these do not replace separable layers.

Production geometry overlays come from `src/lib/scenes/overworld.ts` and the six interior modules. Dashed draft rectangles follow the actual assembled artwork. The overworld's production geometry now matches its artwork (issue 04); the interiors' hit targets still use the earlier scene data until issue 05 promotes them.

## Judge and regenerate — either agent

View each selected reference before judging. Compare **Composition reference** with **Assembled scene**, then both tile densities. Click the scene to inspect a **390 × 844 / 0.6** phone crop. Check props on their furniture, foot contact, perspective, alpha interiors, edges and foreground ordering. Use the geometry toggles to find remaining production alignment work. Inspect moose/rider movement and reduced motion in the overworld. The historical prototype supplies the palette comparison.

If a crop has a hole, fringe or changed shape, reject it even if the validator passes. Correct its prompt, mask or measured bounds and rerun the same command. Save notes and asset hashes under `art/reviews/`. The latest revision supersedes the first batch's visual verdict.

```sh
npm run art:check
npm run art:test
npm run art:validate
npm run check
npm run build
npm test
```

Mechanical checks establish geometry metadata, complete tile coverage, alpha and compatible rig frames. Visual acceptance is a separate decision. Commit accepted layers, prompts, metadata and review notes together. If generation is unavailable, report the failure; do not substitute code-drawn illustrations.

## Explicit API fallback

`npm run art -- generate moosylvania-master --provider api --force` invokes the installed imagegen skill's maintained `image_gen.py`, using the same references and `gpt-image-2`. It requires a locally configured `OPENAI_API_KEY` and the CLI's Python dependencies. `IMAGE_GEN_CLI` overrides the script path; `ART_PYTHON` selects Python. API usage is separately billed; there is no automatic provider switch. Never put credentials in manifests, prompts or committed files.
